# 更新・保存と公開の判定

変更は一つの目的に限定して公開する。今回の目的は保存失敗からの復旧と更新状態の可視化。CSS整理の未確定作業を混在させない。

## 自動判定

- `npm test`：ドラフト規則と102枠の整合性。
- `npm run build` と `npm run test:offline`：生成物、キャッシュ欠損修復、更新失敗時の旧版保持。
- 公開用ビルドを起動して `node tests/browser/reliability.mjs`：保存容量エラーを注入し、未保存警告、再試行、再読み込み後の保持を判定。390×844→844×390→320×568、200%文字で横はみ出しを判定。Chromium/WebKit。結果は `.artifacts/reliability/results.json` に保存。
- GitHub公開後 `scripts/verify-publication.mjs`：HTML・参照JS/CSS・Service Workerが、その公開ジョブのビルドとバイト単位で一致するか判定。異なる場合はジョブを失敗にする。公開自体を自動で巻き戻す処理ではない。

PASSは記載した検査項目のみ。FAILがあれば修正して再検証する。UNTESTEDは成功と合算しない。ブラウザーの実行環境にPlaywrightが必要。自動公開ジョブは現在、ルール・ビルド・オフライン単体試験と公開一致検査を実行し、ブラウザー試験は公開前にローカルで実行する。

## 今回の比較

- 変更前：保存失敗後は次の状態変更まで再保存できなかった。変更後：使い方画面で保存を再試行でき、未保存時はページ離脱の警告を要求する。モバイルOSによる強制終了では警告が保証されない。
- 変更前：利用中のビルドを識別できなかった。変更後：使い方画面にビルド時刻を表示し、更新確認・失敗・準備完了を案内する。確認成功のみを「最新版保証」とは表示しない。
- 変更前：公開ジョブは配信内容の一致まで調べなかった。変更後：配信内容まで自動比較する。

## 未検証として残す項目

iPhone/Androidの物理端末は利用できていない。ホーム画面へのインストール、OSからの起動、バックグラウンド中断復帰、OSの保存領域削除は未検証。クラウド実機も利用していない。

ローカルWebKitのオフライン再読み込みは自動操作エンジン内部エラーになったため未検証。ChromiumではService Worker経由のオフライン再読み込みと保存保持を確認した。WebKitのオンライン再読み込みをオフライン成功として扱わない。
