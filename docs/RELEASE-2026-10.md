# 2026年10月16日 追加改修

対象は現行版 `/` と独立デザイン版 `/v2/`。ドラフトの順序・制限・保存形式・102枠のポケモンは維持する。

## 設計と表記の根拠

- [Apple Design Resources](https://developer.apple.com/design/resources/) のUIキット、アイコン制作資料、色・書体のリソースを設計参照に使用。WebとAndroidでも利用できるシステム書体、独自のアプリアイコン、Lucideの操作アイコンを使う。AppleのフォントやSF SymbolsをWeb配布物として埋め込まない。
- [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography) に沿って、読みやすい文字の大きさ・太さ・階層を保つ。件数を無理に詰め込むために文字を縮めず、拡大時は折り返しやスクロールで内容へ到達できるようにする。
- [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion) の、短く目的が明確なフィードバック、操作を待たせない動き、動きを減らす設定への対応を反映。ダイアログの出現と選択状態の変化に限定した短い動きとし、常時動く装飾を避ける。
- [Material Layout](https://m3.material.io/foundations/layout/layout-overview/overview) と [Color roles](https://m3.material.io/styles/color/the-color-system/key-colors-tones) に基づき、画面の空間に応じた主領域と補助領域、背景・文字・主操作・選択状態の色を分ける。
- [ポケモンユナイト公式：オールスタードラフト](https://www.pokemonunite.jp/ja/topics/battle/20260415-1/) の「使用禁止投票」「選択」「オールスタードラフト」、および公式の「アタック型」等に表示を統一。短い操作欄には「使用禁止」を使用する。数え方は「匹」。本ツールは大会形式の交互指定を維持し、ゲームの投票機能を実装したものとは表示しない。フィアレスは独自ルールであることを説明する。

## リリース判定

1. 通常の文字サイズ・縦横画面で主要な選択・確定・ページ移動が画面内に収まり、要素同士が重ならない。
2. ページをたどって102枠すべてへ到達できる。検索・絞り込み・リサイズ・最終ページでも候補や操作を失わない。
3. 200%文字では文字を切り捨てず、必要に応じてスクロールで操作できる。キーボードのフォーカスとダイアログ終了が機能する。
4. 全ドラフト形式、次試合、戻す・進む、保存復元、タイマー、版ごとの保存分離が動作する。
5. PWAの導線、マニフェスト・アイコン、両ルートのオフライン再起動を検証する。更新は進行中の操作を勝手に再読み込みしない。
6. ビルド・自動テスト・画面の目視確認を通過した変更だけを公開し、GitHub Actionsと公開URLで確認する。

## 検証範囲

Windows上のChromiumとWebKitで画面サイズ、タッチ設定、文字サイズ、通信遮断等を検証する。物理的なiPhone・iPad・Android・Macでのインストール操作、OSのキーボードやスクリーンリーダーの実機試験とは区別する。

## 実行結果

- `npm run build`、ドラフト20件・ポケモン3件・オフライン6件のテストに合格。
- 現行版は15画面サイズ、独立版は8画面サイズをChromium／WebKitで確認。修正後の小画面・横画面・200%文字サイズを再検証し、重なり・横方向のはみ出し・操作欄の欠落を解消。
- 両版のページ送りで102枠すべてに重複なく到達。検索・絞り込み後のページ補正、選択解除、キーボード操作、リサイズを確認。320×568の標準文字では両版とも6匹を表示し、画面全体のスクロールなしで選択・確定できる。
- 現行版の全3形式と独立版の全16手順、戻す・進む、並び替え、次試合の制限、保存復元、タイマーを検証。基本テストではBO3／5／7も確認。
- 両版・2画面サイズ・2エンジンの8条件で、操作部品の名前、フォーカス、文字拡大、動きを減らす設定、画面高が短くなった場合の操作を確認。
- PWAは両版・両エンジンで通信遮断後の再起動と画像表示、保存復元、キャッシュ欠損の検出・修復、更新待機・全ウインドウ終了後の更新を検証。Chromiumのインストール要件診断はエラー0件。5種類の端末・起動状態の案内を模擬検証。

ブラウザー試験は `tests/browser/*-audit.mjs`、`*-pagination.mjs`、`studio-resize-timer.mjs`、`release-accessibility.mjs`、`pwa-release.mjs` に保存。結果とスクリーンショットはローカルの `.artifacts/` に出力する。`NODE_PATH` にPlaywrightのインストール先、`PLAYWRIGHT_BROWSERS_PATH` にブラウザー実行環境を設定して実行できる。
