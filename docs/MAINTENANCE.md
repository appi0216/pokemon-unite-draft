# 更新とバージョン管理

## 普段の更新

1. Codexに修正内容を伝えます。先に確認したい場合は「公開前にプレビューを見せて」と添えます。
2. ローカルで修正・表示確認を行います。大きな変更は作業用ブランチで進め、確認後にmainへ取り込みます。
3. 変更のまとまりごとに、内容がわかる名前でコミット（履歴への保存）します。
4. mainをGitHubへPushすると、GitHub Actionsが検証・公開します。
5. [Actions](https://github.com/appi0216/pokemon-unite-draft/actions)が成功したら、[公開サイト](https://appi0216.github.io/pokemon-unite-draft/)で確認します。以前の画面が残る場合は一度再読み込みしてください。

コミットには識別番号が付き、過去の内容が残ります。公開前のプレビューだけでは公開サイトは更新されません。

## 直前の更新を取り消す

Codexに「直前の公開更新を取り消して、再公開して」と依頼できます。

自分で操作する場合はGitHub Desktopで次の手順を使います。

1. 対象リポジトリのmainを選び、Fetch origin / Pull originで最新にします。
2. Historyを開き、**取り消したい変更のコミット**を右クリックします。
3. Revert Changes in Commitを選びます。
4. Push originを押します。取り消しが新しい履歴として記録され、自動で再公開されます。

「戻したい古い版」ではなく「取り消したい変更」を選んでください。複数の更新を取り消す場合は新しい順に行います。競合が表示された場合は、競合の内容をCodexに伝えてください。

出典: [GitHub公式の取り消し手順](https://docs.github.com/en/desktop/managing-commits/reverting-a-commit-in-github-desktop)

## 節目の版を残す

大きな更新ではGitHubのReleasesからタグ（例: v1.0.0）と変更内容を登録すると、版を見つけやすくなります。タグだけでは公開サイトは切り替わりません。特定の版に戻す場合は「このタグ／コミットの状態に戻して再公開して」と依頼してください。

準備画面のレイアウト改善前の基準コミット: `7d62bf8`。

履歴を消す強制Pushは使わず、取り消しも新しいコミットとして残す運用にします。アプリの版を戻しても、端末内のドラフト保存データを過去に戻すことはできません。
