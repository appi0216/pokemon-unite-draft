## 発見と修正

- **検索0件で画面が伸び続ける不具合**：現行版のカード行数計算と空表示の最小高さが互いに作用していた。空表示は1行で描画し、カード行数の計算と分離。高さが時間経過で増えないことも回帰試験に追加。
- **進行状況を開くと操作欄が一覧に重なる**：狭い縦画面で、展開内容の高さが一覧に割り当てられていなかった。必要な高さを確保して文書スクロールを許可。
- **検索アイコンの縮小**：現行版の入力欄が狭いと虫眼鏡が押し潰されていた。アイコンの幅・高さと縮小しない指定を追加。
- **確認ボタンの不統一**：バックアップ読込の標準ボタン、Draft 02の上書き確認のメニュー風ボタンを、それぞれの版の主操作・副操作のスタイルに統一。キャンセルは左、実行は右。文字拡大時はボタン内で折り返す。
- **設定画面の旧配色**：現行版の検索欄、ホバー、チェックボックス、バックアップ入力に残っていた青緑の色を、現在の紫・ニュートラル色に統一。プリセット名と3操作は行を分けて整列。
- **履歴と結果保存の旧配色**：履歴カードと保存リンクを現行版の色に統一し、保存リンクの文字を拡大。ダウンロードする結果画像も同じ背景・文字・チーム色に揃える。
- **ダイアログの通知が背景に隠れる**：プリセット保存、読込失敗、画像出力失敗等の通知を対象ダイアログ内に表示。正しいバックアップを選んだ後は以前の読込エラーを消去。
- **進行状況の表記**：使用禁止・選択の表記を操作画面に合わせる。
- **並び順と履歴の操作状態**：開いている並び順ボタン、選択済みのチェック、ホバー色と履歴ボタンの強調にも残っていた旧配色を整理。完了後の履歴ボタンの発光を抑え、現在の紫系統で統一。

## 検証方法と範囲

`tests/browser/transitions-audit.mjs` で実際の操作をたどり、320×568、667×375、1280×800をChromium／WebKitで確認。小画面の全ダイアログは200%文字でも確認し、Draft 02の各ダイアログは明暗の両方を記録する。スクリーンショットの上端・下端、横はみ出し、パネルの重なり、ボタン内のはみ出し、操作アイコンの寸法・欠け、画像の読込失敗を確認する。

記録は `.artifacts/transitions-compact-final/` と `.artifacts/transitions-wide-final/`。両版×3サイズ×2エンジンの12条件・366状態が成功し、検出した重なり・横はみ出し・アイコンの欠け・画像読込失敗・実行時エラーは0件。結果画像とJSONのダウンロードも確認した。履歴の最終配色変更後は現行版4条件・118状態を再確認し、並び順メニューとリセット後の先攻選択を含む追加38状態も成功した。

並び順と履歴の操作状態の配色を仕上げた後、現行版の320×568を両エンジンで再検証し、76状態が成功（`.artifacts/transitions-colors-final/`）。文字拡大時や長いダイアログは、内容を切らずスクロールで到達できることを優先する。最終ビルドとオフライン6試験も成功。検証スクリプトは `AUDIT_URL` を指定して公開URLにも同じ操作を実行できる。

インストール・オフライン・更新・保存失敗の専用試験は既存の `pwa-release.mjs` と `recovery-audit.mjs` を使用。OS側のインストール画面、物理端末のキーボード、スクリーンリーダー実機は今回のブラウザー試験には含まない。
