# UI基盤と操作ルール

## スタイルの管理

- `src/ui-tokens.css`：画面幅・高さに応じた文字、操作部品、アイコン、余白、フォーカス線、タイプ別配色の共通定義。
- `src/responsive-controls.css`：共通定義を利用する操作部品、ホーム、ダイアログ、試合履歴のレスポンシブ配置。
- `src/workspace-layout.css`：ドラフト領域・チーム・一覧・履歴レールの配置。
- `src/setup-refresh.css`：ホームの基本構成。
- `src/legacy.css` 以下：既存の画面と細部の互換スタイル。全廃したわけではない。移行時は表示を比較しながら不要な宣言を削除する。

新しいサイズ基準はui-tokensへ追加し、同じ要素を末尾のCSSで再上書きし続けない。タッチ操作の最小寸法と表示密度は別々に検討する。画面サイズだけでなく文字拡大と入力方式も検証する。

## 操作の契約

|操作|マウス・タッチ|キーボード|
|---|---|---|
|ポケモン／スキップの選択|カードを押す|Tab・矢印キーでフォーカス、Spaceで選択|
|確定|中央の決定を押す|カードでEnter、または決定ボタンを押す|
|選択解除|別のカードを選択、ページ変更で解除|Esc|
|一覧ページ|矢印・左右スワイプ|Page Up／Page Down、一覧端の矢印キー|
|履歴ページ|矢印・左右スワイプ|履歴にフォーカスしてPage Up／Page Down|
|直前の確定を取り消す|1つ戻す|1つ戻すボタン、既存のUキー|

スキップも選択段階では試合を進めず、確定時だけ進める。スワイプに伴うクリックは抑止するが、新しいタッチ操作は受け付ける。複数指による操作はページ送りと判定しない。ページの両端で循環しない。

## 検証

変更時は選択、解除、確定、取り消し、スワイプ、ページ端、全102枠、試合遷移を確認する。ブラウザー上の検証と実物端末の検証を区別して記録する。
