# UI検証記録 — 2026-10-15

## 環境

Windows上の実ブラウザーエンジン Chromium 151.0.7922.34 / WebKit 26.5 をPlaywrightから操作。
モバイル幅ではタッチ入力を有効にした。物理的なiPhone・iPad・Macでの検証ではない。

## 確認結果

| 対象 | 結果 |
| --- | --- |
| 既存ドラフトルール・タイマー・保存互換性 | 20テスト成功 |
| 公式102枠、追加3体、全WebPの復号・透過・寸法 | 3テスト成功 |
| オフラインのルート/プロジェクトパス | 2テスト成功 |
| 下記12画面サイズ × 2エンジン | 準備、先攻選択、全16選択、完了、undo/redo、次試合・履歴ダイアログを完走。ページ横はみ出し・JSエラー・画像取得失敗なし |
| 通常 / オールスター / フィアレス × 2エンジン | 検索・解除、役割フィルター、矢印/Enter、undo/redo、途中の連続リサイズ、完了後交換、次試合、保存復元が成功 |
| 320px幅の追加確認 | 名前欄の展開、長いチーム名、タイマー、フィルター、リセット、設定ダイアログが操作可能 |
| 文字拡大 | 640×450でroot文字サイズ200%に変更し、横はみ出しなく選択・確定可能。OSのDynamic Type試験とは別 |
| 通信遮断後の起動・保存復元 | 検証用サーバーの接続を切断。両エンジンで再読み込み→BAN→再読み込み→選択1件復元を確認。画像失敗なし |
| PWAの設定 | standalone、scope/start_url、アイコン、111ファイルのキャッシュを確認。Chromiumのinstallability診断エラーなし |

画面サイズ（CSS px）: 320×568、375×667、390×844、430×932、667×375、844×390、768×1024、820×1180、1024×768、1280×720、1440×900、1920×1080。

目視確認で見つかったヘッダーの重なり、横向き時の過大な一覧高さ、操作アイコンの縦並びを修正。影響する320/390px縦画面と667/844px横画面を両エンジンで再検証。

進行サマリーにフォーカスしたEnterが確定操作にならないことを回帰確認。
オフライン検証で`Vary: Origin`のある静的ファイルがプリキャッシュと一致しない問題を発見し、同一オリジンの静的キャッシュ照合を修正、テストにも追加した。

## 再実行

```sh
npm test
npm run build
npm run test:offline
```

ブラウザー試験はPlaywrightとChromium/WebKitを利用できる開発環境で実行する。アプリの通常実行には不要。

```sh
# 別ターミナルでローカルサーバーを起動
npm run dev -- --port 5174
node tests/browser/responsive-audit.mjs
node tests/browser/interaction-audit.mjs
```

`AUDIT_URL`で検証先を変更できる。結果・画面画像は`.artifacts/`に出力し、失敗時は終了コード1を返す。

## 未確認の範囲

物理端末のSafari、ホーム画面へ実際に追加した後の表示、ソフトウェアキーボード、ノッチ/ホームバーの実寸、VoiceOverは未確認。
`safe-area-inset-*`、可変viewport、44px以上の主要操作領域、スクロール、フォーカス表示、reduced-motionを実装したが、実機合格と同義ではない。
WebKitのオフラインエミュレーションは内部エラーになったため、上記の実サーバー接続遮断で確認した。standaloneメディアのエミュレーションは非対応だったため、設定確認と実機試験を区別する。
