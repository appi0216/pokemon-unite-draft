# UI検証記録 — 2026-10-15

## 追加改修の検証

前回の「横はみ出しなし」だけの検査では、sticky操作バーによる重なりと、その配置が空いたように見える領域を検出できていなかった。今回の改修では下記を追加した。

- `workspace-audit.mjs`: 15サイズ × Chromium/WebKit。ヘッダー、チーム切り替え、一覧、操作欄、検索・並び順・絞り込みの交差を計測。操作欄の画面内表示、下部の過大な空白、パネル外への切れ、文字の欠け、画像失敗を検査。
- 長いチーム名とタイマーを併用し、一覧・チーム・選択・絞り込みダイアログ・200%文字の各状態を操作。200%では文字そのものをremで拡大する。高さ不足時の文書スクロールは許容し、内容が隠れないことを検査。
- 追加のサイズ: 600×800、640×450、1000×700。ほかは下記の12サイズ。
- フォント拡大で見つかった固定ラベル高さと低い画面の補助表示の切れを修正し、影響する320×568、375×667、640×450、667×375、844×390を両エンジンで再検証。全チェック成功。
- `responsive-audit.mjs`: 下記12サイズ × 2エンジンで、準備→全16選択→完了→undo/redo→次試合→履歴を再実行し成功。
- `interaction-audit.mjs`: 3形式 × 2エンジンで、検索、絞り込み、キーボード、途中の画面サイズ変更、入れ替え、次試合、保存復元を再実行し成功。

目視確認には縦画面・横画面・デスクトップ・チーム画面・文字拡大・フィルターのスクリーンショットを使用。実際のiOS/macOS端末のOS挙動やインストール操作まで確認したものではない。

```sh
node tests/browser/workspace-audit.mjs
```

PlaywrightとChromium/WebKitを用意し、開発サーバー起動後に実行する。`AUDIT_URL`、`AUDIT_OUT`、`AUDIT_SIZES`、`AUDIT_ENGINES`で検証条件を指定できる。

## 環境

Windows上の実ブラウザーエンジン Chromium 151.0.7922.34 / WebKit 26.5 をPlaywrightから操作。
モバイル幅ではタッチ入力を有効にした。物理的なiPhone・iPad・Macでの検証ではない。

## 再実行

```sh
npm test
npm run build
npm run test:offline
```

ブラウザー試験はPlaywrightとChromium/WebKitを利用できる開発環境で実行する。アプリの通常実行には不要。

```sh
# 別ターミナルでローカルサーバーを起動
npm run dev -- --port 5174
node tests/browser/responsive-audit.mjs
node tests/browser/interaction-audit.mjs
```

`AUDIT_URL`で検証先を変更できる。結果・画面画像は`.artifacts/`に出力し、失敗時は終了コード1を返す。

## 未確認の範囲

物理端末のSafari、ホーム画面へ実際に追加した後の表示、ソフトウェアキーボード、ノッチ/ホームバーの実寸、VoiceOverは未確認。
`safe-area-inset-*`、可変viewport、44px以上の主要操作領域、スクロール、フォーカス表示、reduced-motionを実装したが、実機合格と同義ではない。
WebKitのオフラインエミュレーションは内部エラーになったため、上記の実サーバー接続遮断で確認した。standaloneメディアのエミュレーションは非対応だったため、設定確認と実機試験を区別する。
