# 更新・保存と公開の判定

## 2026-10-19 Androidエミュレーター実測

Android 16 / Pixel 7仮想端末 / Chrome 133.0.6943.137で公開URLを検証。物理端末の試験ではない。

- OS回転：縦412×783、横863×304 CSSピクセルでホーム画面の横はみ出しなし。
- OS文字倍率1.0/2.0：設定変更後のホーム表示を確認。Web文字すべての2倍拡大を証明するものではない。
- OSのWi-Fi・モバイル通信を無効にして再読み込みし、ドラフト保存内容の一致を確認。通信復旧も確認。
- ChromeのInstall操作後、Androidランチャーの追加確認を確定。ホーム画面アイコンから起動し `display-mode: standalone` を実測。
- 通信を無効化しChromeを強制終了した後、ホームアイコンから再起動。standalone=true、online=false、保存データあり、ドラフト一覧25枚表示を確認。

WebAPKパッケージの存在は確認できなかったため、上記はホーム画面からの単独Webアプリ起動の合格であり、WebAPK配布の合格ではない。iOSはMac不在で未検証。証拠は `.artifacts/android-emulator/`。Android側の導入と上記検証は完了。残るCSS監査の自動再開状況は作業記録で管理する。

変更は一つの目的に限定して公開する。今回の目的は保存失敗からの復旧と更新状態の可視化。CSS整理の未確定作業を混在させない。

## 自動判定

- `npm test`：ドラフト規則と102枠の整合性。
- `npm run build` と `npm run test:offline`：生成物、キャッシュ欠損修復、更新失敗時の旧版保持。
- 公開用ビルドを起動して `node tests/browser/reliability.mjs`：保存容量エラーを注入し、未保存警告、再試行、再読み込み後の保持を判定。390×844→844×390→320×568、200%文字で横はみ出しを判定。Chromium/WebKit。結果は `.artifacts/reliability/results.json` に保存。
- GitHub公開後 `scripts/verify-publication.mjs`：HTML・参照JS/CSS・Service Workerが、その公開ジョブのビルドとバイト単位で一致するか判定。異なる場合はジョブを失敗にする。公開自体を自動で巻き戻す処理ではない。

PASSは記載した検査項目のみ。FAILがあれば修正して再検証する。UNTESTEDは成功と合算しない。ブラウザーの実行環境にPlaywrightが必要。自動公開ジョブは現在、ルール・ビルド・オフライン単体試験と公開一致検査を実行し、ブラウザー試験は公開前にローカルで実行する。

## 今回の比較

- 変更前：保存失敗後は次の状態変更まで再保存できなかった。変更後：使い方画面で保存を再試行でき、未保存時はページ離脱の警告を要求する。モバイルOSによる強制終了では警告が保証されない。
- 変更前：利用中のビルドを識別できなかった。変更後：使い方画面にビルド時刻を表示し、更新確認・失敗・準備完了を案内する。確認成功のみを「最新版保証」とは表示しない。
- 変更前：公開ジョブは配信内容の一致まで調べなかった。変更後：配信内容まで自動比較する。

## 未検証として残す項目

iPhone/Androidの物理端末は利用できていない。物理端末でのホーム画面へのインストール、OSからの起動、バックグラウンド中断復帰、OSの保存領域削除は未検証（Android仮想端末の結果は冒頭を参照）。クラウド実機も利用していない。

初期検証ではローカルWebKitのオフライン再読み込みが自動操作エンジン内部エラーで未検証だった。後述の追加検証では通信先切断方式で確認済み。ChromiumではService Worker経由のオフライン再読み込みと保存保持を確認した。WebKitのオンライン再読み込みをオフライン成功として扱わない。

## 2026-10-18 追加検証

`tests/browser/update-lifecycle.mjs` を追加。公開用ビルドのHTML識別子だけを変更したA/Bの2版を用い、Chromium・WebKitで以下が合格した。過去の別データ形式からの移行試験ではない。

- 2タブを開いている間、新版Service Workerが待機し、再読み込みしても旧版が表示される。
- 両タブを閉じると新版に切り替わり、進行中ドラフトの保存内容が一致する。
- HTTPサーバーがすべての接続を切断する状態でも新版を再読み込みでき、保存内容が一致する。
- 通信復旧後の更新確認が成功する。

WebKitの `context.setOffline(true)` による内部エラーは残るが、通信先を切断する独立した方法でキャッシュからの再読み込みを確認できた。この方法ではOSのオフライン表示・機内モードそのものは試験していない。

公開版でもホーム4サイズ、履歴・ダイアログ3サイズ、文字拡大、スワイプ、キーボード選択/確定/取消、102枠をChromium/WebKitで再確認した。

2026-10-18時点では端末エミュレーターは実施できていなかった。adb/emulator/xcrunのコマンドと標準Android SDK配置が見つからず、接続済みのクラウド実機環境もない。したがって「実機なしで世の中の全検証が完了」とはしない。この時点のブラウザー試験は完了していた。その後のAndroid導入・検証結果は冒頭の2026-10-19節が現在の状態であり、iOSは引き続きMac不在で未検証。

## 対応範囲の根拠（2026-10-20）

ビルドのtarget:es2022はJavaScript出力の設定であり、CSSレイヤーや論理プロパティの対応ブラウザー下限を定める契約ではない。現在確認済みのChromium/WebKitとAndroid仮想端末を、全ブラウザー・実機での保証に拡張しない。CSS監査で互換用指定を削除する際は、対応範囲を別途確認する。
